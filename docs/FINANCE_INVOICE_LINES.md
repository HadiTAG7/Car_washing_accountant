# بنود الفاتورة المختلفة داخل مصدر واحد

امتداد لمسار صندوق العمل المالي المعتمد، وليس مسار ترحيل أو سياسة ضريبية جديدة. لا يغيّر السجلات القديمة تلقائيًا.

## نفس المسار للواجهة وأداة سويتر

تستخدم الواجهة و`sweater_finance_workbench` و`sweater_finance_workbench_save` الخدمة نفسها. يبقى `preview` ثم `save` ثم `approve` ثم `post` إجراءات مستقلة، ببصماتها الحالية وإعادة القراءة. لا حاجة إلى عمود أو جدول جديد: تحفظ البنود داخل `finance_metadata.invoiceLines` الموجود من نوع JSON.

عند استخدام البنود، أرسل `patch.invoiceLines` واحذف `patch.quantity`؛ لا ترسل كمية إجمالية لوحدات مختلفة. يظل `patch.amount` إجمالي المصدر المثبت وبنفس أساس السعر والضريبة الحالي. لا يُستنتج الإجمالي أو الضريبة أو السداد أو التمويل من عدد البنود.

```json
{
  "invoiceLines": {
    "version": 1,
    "items": [
      { "id": "source-line-1", "description": "بند اختبار بطول متر", "quantity": 1,
        "unit": "متر", "unitCost": 12, "amount": 12, "sourceRef": "TEST invoice: line 1" },
      { "id": "source-line-2", "description": "قطعة اختبار", "quantity": 2,
        "unit": "قطعة", "unitCost": 19, "amount": 38, "sourceRef": "TEST invoice: line 2" }
    ],
    "vatAllocation": null
  }
}
```

هذه أسعار اصطناعية لا تعبئ أي فاتورة حقيقية. الحد 100 بند. لكل بند معرّف ثابت فريد، ووصف، وكمية موجبة، ووحدة المصدر، وسعر غير سالب، ومبلغ بالهللة، ومرجع إلى البند الأصلي. يجب أن يطابق حاصل الكمية والسعر مبلغ البند وفق تقريب المبالغ الحالي، ومجموع البنود إجمالي المصدر. لا تجمع الكميات المختلفة ولا تستخرج متوسطًا لسعر الوحدة. السعر أو الكمية المفقودان لا يُخترعان لإمرار الحفظ.

إذا كان سعر الوحدة المطبوع **قبل الضريبة** وإجمالي السطر المطبوع **شاملًا لها**، تحفظ القيمتان كما طبعتا: أضف إلى البند `amountSource: "printed"` و`unitPriceMode: "exclusive"` و`amountNote` يوضح اختلاف الأساس وتقريب المورد، مع `priceMode: "inclusive"` للمستند. والعكس ممكن عند ثبوت أساسه من المصدر. لا تُحسب ضريبة سطر غير مطبوعة، ولا يُعاد حساب الإجمالي المطبوع من سعر وحدة مقرب؛ مثل سعر وحدة قبل الضريبة 13.04 وكمية 2 وإجمالي مطبوع 30. يبقى 30، ولا يستبدل بإجمالي محسوب 29.99. إذا كان الأساسان متطابقين يستمر شرط تطابق حاصل الكمية والسعر؛ وسم «مطبوع» لا يتجاوزه.

المبلغ المشترك الذي لا يفصل المورد أسعار مكوناته ليس تصريحًا باختراع أسعار بنود. يمكن حفظه **دون توزيع** داخل `sharedTotal` مع بنود كمياتها ووحداتها مثبتة، وأسعارها ومبالغها الفردية `null`:

```json
{
  "version": 1,
  "sharedTotal": { "amount": 2950, "description": "أصناف مختلفة والتركيب مشمول دون تفصيل سعره", "sourceRef": "TEST common invoice total" },
  "items": [
    { "id": "item-a", "description": "جهاز اختبار أول", "quantity": 1, "unit": "جهاز", "unitCost": null, "amount": null, "sourceRef": "TEST invoice line 1" },
    { "id": "item-b", "description": "جهاز اختبار مختلف", "quantity": 2, "unit": "جهاز", "unitCost": null, "amount": null, "sourceRef": "TEST invoice line 2" }
  ]
}
```

هذا مثال اصطناعي. يطابق المبلغ المشترك إجمالي المصدر مرة واحدة، ولا يجمع مع أسعار فردية أو يقسم على الكميات. يوثّق البيان ما يشمله، مثل التركيب، دون إنشاء كمية خدمة غير مطبوعة. لا يعفي هذا من كميات الأصناف ومراجعها، ولا يقبل مصدرًا لا يثبت كمياته أو لا يحمل دليل المبلغ المشترك. تبقى معالجة الضريبة والتمويل والسداد مستقلة كما في المسار الآخر.

بعد حفظ البنود تكون الكمية وسعر الوحدة الإجماليان `null`؛ تبقى الكميات والأسعار الفعلية في البنود. السجلات المتجانسة القديمة تظل على شرط الكمية والسعر القائم. العودة إلى التمثيل المتجانس تحتاج `invoiceLines: null` وكمية حقيقية مثبتة؛ لا يحدث تحويل تلقائي.

إذا أعاد كاتب قديم تعبئة الكمية أو سعر الوحدة الإجمالي فوق بنود مفصلة، ترفضه بوابة الاعتماد والترحيل المشتركة حتى تعاد معاينة المصدر من صندوق العمل. تُدار البنود من صندوق العمل أو أداة سويتر بهذا العقد، دون استعمال نموذج قديم لصنع سعر إجمالي.

## الضريبة المطبوعة والمؤهلة

للفاتورة الضريبية متعددة البنود التي تطلب خصم المدخلات، يجب التصريح بـ`vatAllocation`:

```json
{ "printedVat": 10.66, "eligibleVat": 6.75, "reviewRef": "TEST existing reviewed tax opinion" }
```

- المبلغ المطبوع يطابق `vatAmount`؛ لا يستبدل بالمبلغ المؤهل.
- `eligibleVat: null` يعني الأهلية غير محسومة؛ لا يساوي صفرًا ولا خصمًا كاملًا.
- لا يتجاوز المؤهل المطبوع. المبلغ المؤهل الموجب يحتاج مرجع المراجعة نفسه في `taxReviewRef`.
- الخصم الجزئي يبقى موقوفًا ما لم يطابق عقد مصدر مراجع على الخادم. الاستثناء المحدد الوحيد هو فاتورة تجهيز السكن `21110110175500` بمبلغ `81.75` والرأي `TAX-HOUSING39-PARTIAL-20261026`: مطبوعة `10.66`، مؤهلة `6.75`، ومستبعدة ضمن التكلفة `3.91`. لا تُستنتج أهلية جديدة من المرجع وحده.
- لا توجد أهلية افتراضية، ولا يستنتج القرار من الضريبة المطبوعة أو مجرد وجود مرجع. بقية شروط الضريبة والسياسة التاريخية تبقى نافذة.

## الضوابط التي تبقى

البنود تدخل في بصمة المصدر والمعاينة والتدقيق. تغيير وصف أو كمية أو سعر أو مبلغ أو مرجع أو توزيع ضريبة يبطل الاعتماد السابق، حتى لو لم تتغير مبالغ القيد الإجمالية. الحفظ لا يعتمد ولا يرحّل، والاعتماد لا يسدد. تبقى موانع التمويل والتاريخ والدليل والتصنيف والتكرار والفترات المقفلة والمصادر المرحلة كما هي.

هذا التمثيل لا يوزع فاتورة واحدة على حسابات وتصنيفات متعددة، ولا يعالج حالة تقسيم مستند إلى مصدرين أو استثناء المالك من الكمية. تبقى هذه الحالات مستقلة، ولا تستخدم أصنافًا أو كميات وهمية بدلها.

## تنفيذ رأي المصدر ذي الخصم الجزئي

يربط `functions/src/financeReviewedVat.js` الرأي بالمصدر القائم ونوعه، وهوية أصل Drive، والمورد ورقم الفاتورة والتاريخ والمبلغ والنسبة والأساس، والسبعة بنود بأوصافها وكمياتها وأسعارها وإجمالياتها، والمبلغين المطبوع والمؤهل ومرجعهما نفسه. لا يمكن استعمال العقد لمصدر جديد أو فاتورة أخرى، ولا استبدال المؤهل بصفر أو بالمطبوع كاملًا. التخصيص غير المحسوم يظل قابلًا للحفظ كمراجعة معلقة دون اعتماد أو ترحيل.

تُطبّق النتيجة بعد محرك السياسة التاريخية القائم؛ عدم التسجيل أو السياسة المجهولة لا يتجاوزهما العقد. يظل حساب المصدر الذي يختاره المحول كما هو: `1500` مدين `75`، و`1200` مدين `6.75`، و`1020` دائن `81.75` عند السداد البنكي الموثق. هذا وصف للمعاينة وليس إنشاء قيد إنتاجي أو قرار رسملة جديدًا.

تتطابق معاينة العميل والخادم، ويسجل القيد لقطة الرأي والمطبوع والمؤهل والمستبعد. تدخل نسخة العقد في بصمة السياق والاعتماد، وتظل هوية المستند والتكرار والأقفال والفترات والتمويل والاعتماد المنفصل نافذة. لا ينشئ هذا التغيير إقرارًا أو مطالبة أو تعديلًا لإقرار سابق.

## التحقق

## خصم مطبوع على إجمالي الفاتورة

يمكن أن يحمل `invoiceLines` خصمًا واحدًا موجبًا مثبتًا بمصدره، دون توزيعه أو اختلاق بند سالب:

```json
{ "printedDiscount": { "amount": 0.10, "description": "الخصم الإضافي المطبوع", "sourceRef": "TEST invoice-level Extra Dis" } }
```

هذا مثال اصطناعي. مجموع البنود قبل الخصم يبقى محفوظًا، و`invoiceLinesTotal` يطرح الخصم مرة واحدة فقط لمطابقة إجمالي المصدر. يجب أن يكون أقل من مجموع البنود، ولا يقبل مرجعًا فارغًا أو مبلغًا سالبًا أو صفريًا أو مفاتيح إضافية. لا يجمع مع `sharedTotal`؛ أسعار البنود المعروفة لا تُمحى لتسوية فرق الإجمالي.

للمصدر القائم `8YAyIItUAuqW0XEY4hV7`، فاتورة `61355`، يربط الخادم العقد بأصلها وموردها وتاريخها وضريبتها ومرجعها وبنودها الأربعة: الكميات 3/3/3/1، وأسعار الوحدة قبل الضريبة 30/8/15/15، والإجماليات المطبوعة 103.50/27.60/51.75/17.25. مجموعها 200.10، وخصم الإجمالي 0.10، والنهائي 200. الضريبة المطبوعة تبقى 26.10، والمجموع المطبوع قبل الضريبة 174 محفوظ ضمن حقائق العقد. صافي حساب الأصل بعد خصم الإجمالي يظل 173.90 وفق المحول القائم (`200 - 26.10`)؛ لم يتغير حساب القيد أو التصنيف أو الضريبة.

التمويل غير المحسوم يبقى مانعًا. تدخل أدلة الخصم ضمن بصمة المصدر والسياق والتدقيق؛ تغييرها يبطل الاعتماد ولو لم يتغير مبلغ القيد. لا تحفظ التقنية هذا التمثيل على المصدر الحقيقي كتجربة.

## فحوص الإصدار

اختبارات الوحدة والواجهة وأداة الوكيل، ثم اختبارات المعاينة والحفظ والاعتماد والترحيل والرفض والتكرار في محاكي `demo-sweater-finance` فقط. تحقق مستقل من اختبار النظام 12، ثم قراءة وقبول مالي من 1. فحص الإنتاج قراءة فقط؛ لا تُملأ المصادر الحقيقية أو تُعتمد أو تُرحّل كتجربة للنشر.
