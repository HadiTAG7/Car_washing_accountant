# استثناء عدد موثق وتوزيع أصل قائم

امتداد محدود للعقد `FINANCE_INVOICE_LINES.md`، من خلال خدمة صندوق العمل المالي نفسها للواجهة وMCP. لا حساب مالي أو تمويل أو سداد أو ضريبة جديدة، ولا كتابة تلقائية على سجل قائم عند النشر.

## استثناء العدد

ثبت جواب هادي للسؤال 10 بتاريخ 26 أكتوبر 2026: «10 مو مهم العدد». نطاقه مستندان قائمان فقط: المفاتيح بمبلغ 20 ريالًا والنحاس بمبلغ 150 ريالًا. لا يمنح عددًا فعليًا، ولا يجيز اختراع كمية 1 أو تفسير طول النحاس كعدد قطع.

توجد منح مصدر محدودة ومراجعة في `functions/src/financeSourceEvidence.js`. كل منحة تربط نوع السجل ومعرّفه ومبلغَه وهوية مستنده ومرجع القرار ونصه وتاريخه. ليست إعدادًا قابلًا للتحرير من الواجهة، ولا يقبل الخادم ادعاء قرار مالك لمصدر آخر. إضافة مصدر أو تغيير المبلغ أو هوية مستنده يحتاج مراجعة جديدة، ولا يُستنتج من تأشير المستخدم.

يعرض `read.sourceContext.quantityGrant` المنحة المتاحة، ثم يُرسل التصحيح:

```json
{
  "invoiceLines": null,
  "quantityException": {
    "version": 1,
    "grantRef": "المرجع العائد من قراءة الخادم لهذا المصدر",
    "sourceRef": "مرجع المستند ودليل المراجعة الفعلي"
  }
}
```

احذف `patch.quantity`؛ تحفظ الكمية وسعر الوحدة `null`. لا يُحوّل المبلغ إلى سعر وحدة. التحذير يبقى ظاهرًا، والحفظ لا يعتمد ولا يرحّل. تبقى نواقص المورد والتاريخ والسداد والتمويل والضريبة كما هي. لا يسمح بهذا التمثيل لإنشاء مصدر جديد أو مع البنود المختلفة.

## أصل الفاتورة 0579

المصدران موجودان قبل هذا التغيير: 200 ريال لبند الدبابات، و80 ريال لبند السكن. أصل الفاتورة نقدي غير ضريبي، وإجماليه 280 ريالًا. بنوده المطبوعة أربعة: 30 و30 و20 و200. لا يمثل ربطهما إنشاء مصروف أو تقسيم مبلغ جديد.

المنحة المراجعة تحتوي قائمة بنود الأصل مرة واحدة، وتعيّن السطر الرابع لمصدر 200، والأسطر الثلاثة الأولى لمصدر 80. التعيينات والمبالغ ثابتة في المنحة المراجعة وليست حقولًا يرسلها العميل. كل سطر له تعيين واحد، ومجموع كل تعيين يساوي مبلغ مصدره، ومجموع المصدرين يساوي سقف الأصل.

يعرض `read.sourceContext.allocationGrant` التوزيع المتاح. يُرسل لكل سجل قائم، بمعاينته وبصمته المستقلتين:

```json
{
  "documentAllocation": {
    "version": 1,
    "grantRef": "المرجع العائد من قراءة الخادم لهذا الأصل",
    "sourceRef": "مرجع مراجعة البنود وتوزيعها من الأصل"
  }
}
```

- يمكن حفظ ربط السجل الأول بينما الثاني لم يربط بعد؛ تبقى بوابة الاعتماد والترحيل موقوفة حتى يكتمل الربطان.
- يقرأ الخادم السجلين داخل المعاملة نفسها. أي تغير في مبلغهما أو رابط الأصل يرفض، وكذلك فقد أحد السجلين.
- لا يقبل مصدرًا ثالثًا لهذا الأصل، حتى مع تغيير صيغة رابط Drive أو معاملاته، ولا يقبل مجموعة بديلة أو تعيينات يرسلها العميل.
- يبقى منع التكرار العام نافذًا خارج المصدرين المحددين. وجود مصروف ثالث مرتبط بالأصل يمنع الاعتماد والترحيل.
- تفحص المنح المقيدة هوية Drive نفسها، لا تطابق نص الرابط فقط. تشمل القراءة أنواع المصروفات الأربعة، حتى 1000 مصدر لكل نوع؛ تجاوز التغطية يوقف الاعتماد والترحيل صراحةً. لا تستخدم نتيجة مخبأة بين محاولات إعادة المعاملة.
- بصمة سياق التوزيع تتضمن المصدرين والمنحة. تغير أي نسخة يبطل الاعتماد أو المعاينة السابقة، حتى عند ثبات إجمالي القيد.
- يعاد التحقق في باب الترحيل المشترك القديم والجديد، مع الفترات المقفلة وحماية المصدر وقفل منع تكرار القيد.
- لا يتيح هذا تحرير مصدر مرحّل أو حذفًا أو دمجًا أو نقل تصنيف أو تغيير رابط للهروب من التكرار.

ربط التوزيع لا يعفي الكميات: السطر الثالث في الأصل لا يبيّن كمية واضحة، والسطر الرابع يطبع كمية 12 وسعرًا 200 وإجماليًا 200. لا يُستخرج سعر متوسط أو كمية مفقودة لتجاوز ذلك. قرار السؤال 10 لا يشمل هذه الفاتورة؛ تبقى نواقصها المستقلة ظاهرة إلى أن تثبت بمعالجة مأذونة.

## هوية أربعة مستندات مراجعة دون رقم مطبوع

الرأي الموجود `TAX-53-SOURCE-OPINION-20261026` يخص أربعة مصادر متغيرة قائمة بمجموع 72 ريالًا: `ABdYfrGUUZ0ywAsy2UQg` (12)، و`LKKDvPXXwkUB2LhGiv6h` (30)، و`var_inv85_2026-09-14` (10)، و`z071wqebTaGVyoueH9FO` (20). لا تضاف أرقام فاتورة من عنوان الملف أو مرجع طلب الفاتورة أو رقم عملية البطاقة. تبقى `invoice_number` فارغة، و`is_tax_invoice` و`vat_deductible` والمبلغ والضريبة والنسبة كما هي. الأول غير قابل للخصم؛ المواقف الثلاثة ذات رأي سابق ضمن الربع الثالث المقدم، وليست مطالبة جديدة.

تعرض القراءة `sourceContext.reviewedIdentityGrant` عندما تطابق الحقائق المثبتة. لا تلحق المنحة تلقائيًا بالمصدر. الربط الصريح بعد المعاينة يستخدم:

```json
{ "reviewedDocumentIdentity": { "version": 1, "grantRef": "<exact sourceContext.reviewedIdentityGrant.ref>", "sourceRef": "<reviewed original evidence>" } }
```

يحفظ داخل `finance_metadata` الموجود. المنحة مربوطة على الخادم بنوع المصدر ومعرفه، وهوية Drive، والمورد، وتاريخ الفاتورة، والإجمالي، والضريبة المطبوعة والنسبة والأساس وعلامتي الضريبة ومرجع الرأي السابق. تستثني غياب الرقم المطبوع فقط؛ لا تختلقه ولا تعفي أي نقص آخر. أي مصدر جديد أو حقائق مغايرة أو مرجع مزيف أو دليل فارغ مرفوض. فحص هوية المستند الموحّدة عبر الأنواع الأربعة كامل ضمن سقفه القائم ويفشل مغلقًا عند نقص التغطية.

لا تتغير قواعد التمويل: `employee` و`unknown` يظلان بلا مقابل مفترض، ولا يضاف ربط بحساب 1300. السياسة التاريخية والتصنيف والأقفال والاعتماد النسخي ومنع التكرار تبقى قائمة. بعد الربط، تعالج المواقف وفق رأيها السابق فقط وبعد إثبات السياسة؛ لا تقديم إقرار أو مطالبة ثانية. تسجَّل نسخة المنحة في بصمة السياق والتدقيق ولقطة ضريبة القيد، وتطابق معاينة العميل الخادم. تصحيحات المصادر الحقيقية وتنفيذ المالي لاحقًا منفصلان عن اختبار الإصدار.

## سجل التدقيق

الأدلة تحفظ في `finance_metadata` الموجود، مع سجل قبل/بعد وفاعل وسبب ونسخة وحماية التزامن الحالية. سجل التدقيق يرفق أيضًا نسخة من قرار المالك أو توزيع الأصل المعتمد من الخادم، دون الاعتماد على وصف يرسله العميل. `finance_reviews.sourceContextHash` يربط الاستثناء بنسخة منحته، ويربط اعتماد التوزيع بنسخ المصدرين، دون تغيير أرصدة أو إنشاء جدول جديد.

اختبارات الحفظ والاعتماد والترحيل والتزامن والتكرار والسقف تكون ببيانات اصطناعية ومحاكي `demo-sweater-finance` فقط. يلزم تحقق 12 المستقل وقبول 1 لمعاينات مالية غير حافظة قبل أي تصحيح فعلي لاحق. نشر Vercel لا ينشر Firebase أو قواعده أو وظائفه. أي باب قديم لم يُنشر عقده يظل رافضًا للتمثيل الجديد، وليس مسار تجاوز.
