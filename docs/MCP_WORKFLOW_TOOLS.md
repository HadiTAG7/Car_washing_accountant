# أدوات MCP التشغيلية — إصدار 1.2

تُضاف الأدوات إلى خادم MCP الحالي دون تغيير هوية الاتصال أو مفاتيحه أو أدوار الحسابات. مسارها الموثوق هو `/api/ledger` بهوية Firebase ومراجعة الدور المخزن على الخادم. لا يُنشر Firebase أو تُغيّر قواعده ضمن هذا الإصدار.

## الأدوات

| الأداة | النتيجة |
| --- | --- |
| `sweater_expense_correction_options` | معرّفات التصنيفات والبنود والوحدات الموجودة، مع تنبيه إن كانت القائمة مقتطعة |
| `sweater_preview_expense_correction` | قبل/بعد وبصمة، دون كتابة |
| `sweater_save_expense_correction` | تصحيح أو نقل فاتورة غير مرحلة، مع سبب وبصمة وتأكيد |
| `sweater_payroll_status` | المسيرات وحالة العمال وصافي المستحق حسب شهر محدد |
| `sweater_payroll_preview` | حساب محرك الرواتب دون حفظ |
| `sweater_save_payroll_draft` | حفظ مسودة دون اعتماد أو صرف |
| `sweater_preview_payroll_payment` | مطابقة دفعة خارجية لعمال محددين فقط |
| `sweater_record_payroll_payment` | إثبات سداد مؤكد عبر مسار الرواتب الموجود، بما فيه أثره المحاسبي |
| `sweater_record_worker_advance` | معاينة/تسجيل سلفة مدفوعة فعلاً وشهر إسنادها الصريح، دون ترحيل |

## القيود

- تصحيح المصاريف للمحاسب أو المدير، وإثبات الرواتب والسلف للمدير؛ لا تتوسع أدوار الشركاء أو المشرفين أو المشغلين.
- التصحيح يرفض الأقفال الحالية والقديمة والأثر الدفتري والفترات المقفلة. لا يفتح فترة ولا يعكس قيداً تلقائياً.
- نقل المصروف يحافظ على إجمالي الفاتورة وحقولها وضريبتها ومرفقاتها. تغيير مبلغ فاتورة ضريبية خارج نطاق هذه الأداة. عدد الوحدات حقيقي وتكلفة الوحدة مشتقة بدقة إضافية؛ يبقى إجمالي الفاتورة مصدر المبلغ.
- نقل المصدر وإزالته من التصنيف السابق وتحديث إجماليات الأب وسجل قبل/بعد وإيصال منع التكرار كلها في معاملة واحدة. لا يجوز اختصار النقل بإنشاء نسخة ثم حذف الأصل باستدعاء منفصل.
- أي تغير بالمصدر أو البند الأب أو بنوده منذ المعاينة يستلزم معاينة جديدة. إعادة الطلب نفسه بعد نجاحه تعيد الإيصال ولا تنشئ نسخة أخرى.
- مسير الرواتب مصدر المبلغ؛ لا تعني المعاينة أو المسودة أن الدفع حدث. إثبات دفعة خارجية يتطلب إقرار المستخدم، ويؤثر فقط على العمال المحددين. لا توجد أداة تحويل مصرفي أو اعتماد/دفع شامل جديدة.
- السلفة تحتاج مفتاح طلب ثابتاً ومعرّف العامل وتاريخ دفع حقيقياً وشهر إسناد منفصلاً. السلفة المطابقة للعامل والمبلغ واليوم تُرفض حتى لو تغير مفتاح الطلب، كي تُراجع ولا تتكرر صامتة.
- لا تغيّر كمية خطة تأسيس مشتركة عند تصحيح وحدات فاتورة واحدة. كمية الفاتورة محفوظة على القيد؛ قد يختلف عرض الخطة الإجمالي في الواجهة عن وحدات هذه الفاتورة.
- بعد الحفظ يُتحقق من السجل المستهدف؛ عند خطأ اتصال لا يُفترض نجاح أو فشل. أعد نفس الطلب/المفتاح أولاً للاستفادة من منع التكرار.

## التحقق

اختبارات سلوك ومعاملات معزولة في `functions/test/expenseCorrections.test.js`، واختبارات Firestore حقيقية للتزامن في `expenseCorrections.emulator.test.js` (ترفض أي مشروع غير `demo-sweater`). اختبارات MCP تشمل النقل HTTP وstdio والمخططات والصلاحيات ووضع القراءة وإثبات أن محرك الرواتب الموجود هو المستعمل. لا تُجرى تجربة كتابة على الإنتاج.

القارئ التجريبي لمنصة SSP منفصل؛ هذا الإصدار لا ينقل جلسات Chrome للسحابة ولا يستورد غسلات من SSP.
