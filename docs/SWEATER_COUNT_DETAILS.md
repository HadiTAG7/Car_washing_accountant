# تفاصيل الغسلات المجانية وإلغاءات البايكر والصيانة

امتداد عرض محدود لعقد `sweater-metrics-v1` ومسار `Metrics` الموقع القائم. لا مخزن أو جدول أو endpoint جديد، ولا تغيير إعدادات أو حسابات أو رواتب أو درجات.

الحقل الاختياري `countDetails` يخص `freeWashCompensation` و`cancelledByBiker` و`cancelledMaintenance` فقط. تحافظ كل فئة على عددها ووقت القراءة الأصلي. اللقطات القديمة بلا تفاصيل تظل صحيحة وتعرض القيد بوضوح. لا تُلحق تفاصيل أقدم بعدد من قراءة أحدث، ولا تعاد قراءة قديمة بتاريخ جديد.

كل صف واقعة مقروءة من المصدر، بهذه الحقول بالضبط:

| الحقل | المعنى |
|---|---|
| metricKey | أحد مفاتيح الفئات الثلاث |
| sourceId | معرف الواقعة الأصلي؛ فريد داخل الفئة |
| driverExternalId | معرف البايكر في SSP، أو null إذا لم يُثبت |
| date | تاريخ الواقعة داخل الشهر، أو null إذا لم يُعرض؛ لا تختلق يومًا |
| quantity | عدد وحدات المصدر؛ موجب صحيح، وللإلغاء 1 لكل واقعة |
| amount | مبلغ المصدر الفعلي بالريال إلى هللتين، أو null؛ الصفر المؤكد وحده 0 |
| reason | السبب المعروض في المصدر، أو null؛ لا تستنتجه من المسؤولية المفترضة |
| sourceUrl | رابط دليل نظيف على https://ssp-portal.sweater.sa، بلا أسرار أو رموز دخول |
| bookingId | معرف الحجز المثبت، أو null؛ لا ربط بتشابه الاسم أو الرقم فقط |

كل صف يجب أن ينتمي لنفس فترة ومرشحات ووقت قراءة العدد المرسل معه. لا تُنسخ 9/16/4 القديمة إلى قراءة حديثة؛ إما إعادة قراءة متحققة للعدد وتفاصيله معًا، أو إبقاء الإجماليات القديمة وحدودها. التغطية الجزئية مقبولة وتظهر «المفصل / العدد» و«بلا تفاصيل»، مع رفض مجموع يتجاوز العدد. تُرفض الوقائع المتكررة أو الحجز المكرر داخل الفئة، والحقول الإضافية وبيانات العملاء والرواتب والاعتماد.

`HasCompensation` وحده لا يثبت مبلغًا ولا عدد غسلات تعويض. أعداد الإلغاء ليست خصم راتب أو إدانة. المبلغ المفقود يبقى غير متاح، ولا يحسب من سعر الغسلة. الأسماء للعرض فقط من سجل البايكر بمعرف SSP فريد؛ التعارض أو الفقد لا يحل بالاسم.

يحفظ الخادم التفاصيل كجزء من جسم اللقطة الموقع وبصمتها. الإعادة بنفس المعرف والجسم تقرأ الموجود؛ تغيير أي حقل تحت المعرف نفسه مرفوض. اللقطة الجديدة تحفظ بمعرف جديد، ولا تعدل القديم. تبقى جميع المسارات المالية مستقلة.

إذا كانت لوحة Compensations أو تفاصيلها غير متاحة، فلا ترسل صفوفًا بديلة من التذاكر أو الحجوزات ما لم يثبت ارتباطها بنفس الفئة والعدد والفترة. إيضاح عدم توفر التفاصيل في الواجهة نتيجة مقبولة؛ لا يُملأ الفراغ تخمينًا.

تحديث المرسل المثبت إن لزم يقتصر، بعد المراجعة المستقلة، على عقد المؤشرات وبصمته وقبول `countDetails` الاختياري في مشغّل Metrics. لا تغيير مفاتيح أو مزود أو principal أو CLI/client أو كاتب الغسلات، ولا جدول تشغيل جديد.
