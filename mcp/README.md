# خادم MCP لسويتر

يعطي مساعداً ذكياً — Claude Code أو Claude Desktop أو أي عميل MCP — قدرةً على
قراءة دفاترك والكتابة فيها.

```
تسأل:  «كم ربحي في يوليو؟ وأي مصروف ما عليه فاتورة ضريبية؟»
يجيب:  من ميزان المراجعة وتقرير الضريبة، بنفس أرقام الشاشة.
```

---

## ١ — القرار الذي يحكم كل شيء هنا

**هذا الخادم عميل، لا باب خلفي.**

الطريق السهل كان مفتاح خدمة يكتب في Firestore مباشرة. ولم يُسلَك، لأنه يلغي كل
ما يحمي الدفاتر:

| الضمانة | أين تُفرَض | ماذا لو تُخُطِّيت |
|---|---|---|
| مدين = دائن | معاملة الاستدعاء | قيد غير متوازن في الدفاتر |
| الفترة تُشتَقّ من التاريخ | معاملة الاستدعاء | قيد في شهر خاطئ |
| الفترة المقفلة مرفوضة | معاملة الاستدعاء | تعديل شهرٍ سبق إقراره |
| ترقيم ذرّي | معاملة الاستدعاء | رقمان متطابقان |
| قفل الترحيل | معاملة الاستدعاء | ترحيل السجل مرتين |
| سجل التدقيق | معاملة الاستدعاء | تغيير بلا أثر |

ولاحظ العمود الأوسط: **كلها في مكان واحد**، لأن قواعد Firestore لا تملك حلقةً
ولا طيّاً — فـ«مجموع المدين يساوي مجموع الدائن» على قائمة بطول غير معروف
**غير قابل للتعبير** فيها أصلاً. الأمان هنا ليس حزاماً فوق حزام؛ هو المكان
الوحيد الذي تعيش فيه هذه الضمانات.

فالخادم يسجّل الدخول كإنسان، ويحمل توكناً، ويلتزم بنفس الدور. وكل كتابة تمرّ
بـ `httpsCallable` — نفس الباب الذي يستعمله التطبيق.

واختبار في `test/tools.test.js` يفحص هذا **على المصدر**: لا `setDoc` ولا
`addDoc` ولا `runTransaction` ولا `firebase-admin` في أي ملف هنا. من يحاول
اختصار الطريق لاحقاً يجد اختباراً أحمر لا مراجعة كود.

## ٢ — الحدّ الذي لا تسدّه أي بوابة

القواعد تمنع القيد **غير المتوازن**. لا شيء يمنع القيد **المتوازن الخاطئ**.

فاتورة ٣٤٠ ريال تُقرأ ٣٠٤ تنتج قيداً سليماً قانونياً وصحيحاً حسابياً وخاطئاً
واقعياً — ويمرّ من كل بوابة بنيناها، لأنها تفحص الاتساق لا الصدق.

ولذلك:

- كل كتابة تُرجع ما كتبته — رقم القيد ومعرّفه والمبالغ — فالمحادثة نفسها سجل.
- `sweater_reverse_entry` أداة من الصف الأول: التصحيح بقيدٍ مضاد، لا بحذف.
- `SWEATER_MCP_READONLY=1` يمنع الكتابة بالكامل، ويُخفي أدواتها من القائمة أصلاً.

## ٢-ب — نسختان: محلية وبعيدة

| | المحلية `mcp/server.js` | البعيدة `api/mcp/[secret].js` |
|---|---|---|
| النقل | stdio | HTTP (Streamable) |
| الأجهزة | جهاز واحد | أي جهاز |
| المساعدون | Claude Desktop · Claude Code | **وChatGPT كذلك** — موصِّلاته كلها HTTP |
| السرّ | ملف على جهازك | **رابط عام** |
| الكتابة | متاحة | **معطَّلة افتراضياً** |

**والأدوات هي هي.** `src/tools.js` مستوردٌ في الاثنين كما هو، لأنه لم يعرف
وسيلة نقل يوماً — واختبار يقارن قائمتَي الأدوات ويفشل لو انحرفت إحداهما.

### تهيئة البعيدة

على Vercel ← Settings ← Environment Variables:

| المتغيّر | القيمة |
|---|---|
| `MCP_SECRET` | نصّ عشوائي طويل — هذا هو مفتاحك |
| `SWEATER_EMAIL` · `SWEATER_PASSWORD` | حساب المساعد |
| `MCP_ALLOW_WRITES` | لا تضبطه — إلا حين تقرر فتح الكتابة |

ولّد السرّ بشيء لا يُخمَّن:

```bash
openssl rand -hex 32
```

ثم أضِف في Claude أو ChatGPT موصِّلاً بالرابط:

```
https://<نطاقك>/api/mcp/<MCP_SECRET>
```

### ما يحرس هذا الرابط، ولماذا لا يكفي وحده

الرابط **هو** المفتاح: من يعرفه يدخل. فالحراسة مبنية على أن التسريب وارد:

- **الكتابة معطَّلة افتراضياً** ولا تُعرَض أدواتها في القائمة أصلاً. رابط
  مسرَّب يقرأ ولا يكتب.
- **`timingSafeEqual` لا `===`.** مقارنة النصوص تتوقف عند أول حرف مختلف، فزمنها
  يسرّب طول البادئة الصحيحة حرفاً حرفاً.
- **404 لا 403** للسرّ الخاطئ. ردٌّ يقول «سرّ خاطئ» يؤكّد لمن يجرّب أن العنوان
  صحيح وأن الباقي تخمين.
- **بلا `MCP_SECRET` الخادم يرفض بـ503** بدل أن يقارن بسلسلة فارغة — أي أنه لا
  يقبل رابطاً بلا سرّ في اللحظة بين النشر وضبط المتغيّر.
- **الحساب بدور `accountant` لا `admin`**، فحتى مع كتابة مفتوحة ورابط مسرَّب
  لا يستطيع أحد **إعادة فتح فترة مقفلة**.

وتبديل السرّ = تغيير المتغيّر وإعادة النشر. الرابط القديم يصير 404 فوراً.

> **قارن بالمحلية بإنصاف:** المحلية أقوى أمناً — لا رابط عام أصلاً. البعيدة
> تشتري «أي جهاز، وأي مساعد» بثمن سرٍّ ثابت على الإنترنت. اختر بوعي، وابدأ
> بالقراءة فقط.

## ٣ — التهيئة (المحلية)

**أنشئ حساباً مستقلاً للمساعد** — لا تستعمل حسابك.

1. Firebase Console ← Authentication ← Add user ← مثلاً `you+ai@gmail.com`
2. Firestore ← `users` ← مستند بمعرّف الـ uid ← `role` = `accountant`

لماذا مستقل؟ لأن `audit_logs.userId` يسجّل الفاعل، فيصير سؤال «وش سوّى المساعد
هالأسبوع؟» سؤالاً له جواب. والدور يحدّ ما يستطيعه أصلاً: `accountant` يرحّل
ويعكس ويقفل، ولا يستطيع **إعادة فتح** فترة مقفلة — تلك للمدير وحده.

```bash
npm install --prefix mcp
```

ثم في إعداد عميل MCP:

```json
{
  "mcpServers": {
    "sweater": {
      "command": "node",
      "args": ["/absolute/path/to/Car_washing_accountant/mcp/server.js"],
      "env": {
        "SWEATER_EMAIL": "you+ai@gmail.com",
        "SWEATER_PASSWORD": "…"
      }
    }
  }
}
```

للتجربة بلا أي مخاطرة، أضِف `"SWEATER_MCP_READONLY": "1"`.

| متغيّر | الافتراضي |
|---|---|
| `SWEATER_EMAIL` · `SWEATER_PASSWORD` | مطلوبان |
| `SWEATER_MCP_READONLY` | معطَّل |
| `SWEATER_PROJECT_ID` وبقية إعداد Firebase | إعداد `gemini-eed4a` المدمج |

## ٤ — الأدوات

**قراءة (٩):** `whoami` · `report` (ميزان المراجعة · قائمة الدخل · المركز
المالي) · `vat_report` · `general_ledger` · `journal_entries` · `records` ·
`unposted` · `chart_of_accounts` · `startup_costs`

**كتابة (٨):** `post_source` · `reverse_entry` · `close_period` ·
`reopen_period` · `issue_document` · `void_document` · `startup_entry` ·
`seed_chart`

كلها مسبوقة بـ `sweater_`.

**ما تُلاحظه في مخطَّطات الكتابة أهمّ مما فيها:**

- `post_source` يأخذ `kind` و`sourceId` **فقط**. لا مبالغ ولا حسابات — الخادم
  يبني القيد من السجل نفسه. لو قبِلت الأداة مبلغاً، لجاء الرقم الذي يدخل
  دفاترك من نموذج لغوي بدل السجل الذي يدّعي وصفه.
- `startup_entry` لا يقبل `actualAmount` ولا `status` — كلاهما مشتق على الخادم
  من البنود.
- `reopen_period` يشترط سبباً مكتوباً.

## ٥ — الأرقام لا تُحسب هنا

التقارير تستورد وحدات التطبيق نفسها — `reports.js` و`vatReturn.js`
و`chartOfAccounts.js` — وهي دوال صافية لا تعرف Firebase.

تنفيذٌ ثانٍ كان سينحرف، ويوم ينحرف يقتبس المساعد رقماً يخالفه التطبيق، بثقة
وبلا شيء يبدو خاطئاً. وهذا أسوأ عطبٍ ممكن في أداة محاسبية.

ويقابل ذلك تفصيلٌ تقني: وحدات التطبيق تستورد بلا امتداد (`from './journal'`)
— اصطلاح مُجمِّعات لا ESM. Vite يحلّه وNode لا يحلّه. و`resolver.js` خُطّاف
ضيّق يعالجها داخل هذه الحزمة، بدل تعديل ٦٠٣ استيرادات في ١٢٥ ملفاً من
التطبيق، وبدل نسخ الدوال هنا.

## ٦ — الاختبارات

```bash
npm test --prefix mcp     # ١٧ اختباراً
```

`server.test.js` يشغّل `server.js` **كعملية مستقلة** ويتصل به بعميل MCP حقيقي.
وهذا ليس ترفاً: هو ما كشف أن الخادم لا يقلع أصلاً بسبب الاستيراد بلا امتداد —
عطبٌ لم تكشفه اختبارات الوحدة لأن vitest يستعمل مُحلِّل Vite نفسه، فكان يمرّ
عندها ويسقط عند التشغيل الحقيقي.

ويثبت كذلك أن **سرد الأدوات لا يحتاج بيانات دخول** (الاتصال كسول عمداً: عميل
MCP يسرد عند بدء الجلسة)، وأن خادماً بلا اعتماد **يبقى حياً ويقول أين يُضبط**
بدل أن ينهار — فالانهيار يبدو مطابقاً لمشروع معطوب، فيبحث صاحبه في المكان الخطأ.
